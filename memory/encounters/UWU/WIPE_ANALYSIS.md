# UWU — 團滅原因分析參考 (Wipe Analysis Reference)

**用途**:給 `.claude/skills/wipe-cause-analysis/SKILL.md` 查用的 **UWU 專屬**參考——這隻王的機制特性會如何影響wipe根本原因判讀。跟 `../../../UWU_MECHANICS.md`(死因判讀的主要查表對象)一樣,這份檔案是**給所有分析這個副本的人共用的知識,不是任何一個團隊自己的黑話、名單、或特定一次report的答案**。跟這個資料夾裡其他檔案不同,這份檔案含判讀內容,不是純技能事實表,但仍然要保持跟 `UWU_MECHANICS.md` 一樣的通用性——**某個團隊自己的技能俗稱、特定一場report的pull編號/玩家名字,屬於那個團隊自己的分析紀錄(類比 `analysis.js`,repo刻意不放進git的私有資料),不要寫進這份共用檔案**,以免分析新的report時把「這團隊剛好這樣講/這把剛好這樣」誤認成「UWU機制普遍是這樣」。純技能事實請查 `./README.md` 索引底下的各 `<Boss>.md`。

## 已知的弱訊號模式(FFLogs死亡明細本身查不乾淨時)

- **P2階段,FFLogs死亡明細完全查不到致命技能名稱(`abilityGameID`/`killingAbilityGameID`都是0或空白),全隊在幾秒內近乎同時死亡**:不要直接跳到查無實據的通用結論。這種「查不到名字」是火獄之楔(4根柱子)多根同時炸開、疊加傷害來源太多導致FFLogs無法歸因單一一擊的常見特徵——優先懷疑柱子沒有依序處理,再看有沒有其他跡象支持(例如這把duration是否比P2正常滿血流程久)。
- **死亡明細裡的技能序列對得上 `UWU_MECHANICS.md`「P4 亂擊之究極幻想」整段流程,即使 `data.js` 的 `phase` 欄位標的是P5**:`data.js` 的 `phase` 只記錄「這把wipe時FFLogs認定到達的階段」,P4→P5轉場常常被標成P5,不代表collapse真的是P5三神過場秀本身——要看整段技能序列對上哪個流程,不是只信`phase`欄位。這整套流程收尾是「究極」,`UWU_MECHANICS.md`「一擊必殺類」表格的「究極」列已經寫好死因判讀:「需要開啟坦克3段極限技硬扛,否則團滅」「極限技沒開好通常是團滅而非個人死亡」。看到collapse對上這整套流程收尾,且傷害量級遠超血量上限、明顯補不住(套用skill Step 5的自我挑戰),優先懷疑是這段的坦克三段極限技(LB)開晚了或沒開好,而不是把死因寫成序列裡任何一個較早出現的個別技能——LB時機沒辦法只靠死亡明細100%確認,結論可以寫成「LB可能晚了,需要跟RL確認」,不要因為查不到LB量表就退而求其次改寫成別的技能名稱當結論。

## 技能設計上容易被誤判的地方

- **灼熱咆哮**(P2伊弗利特,P4/P5沿用):隨機點名1名治療疊層AOE。**機制設計是被點名的人自己不會被自己疊層的AOE打到,沒走位閃開的旁人才會**——FFLogs死亡明細看到這個技能打死好幾個人時,要另外確認誰是這次被點名疊層的治療、她走位是否正確,不能只看誰真的斷氣。
- **地火噴發**(P2伊弗利特,P4沿用):對距離最遠的2名非灼熱咆哮目標玩家做4連點名AOE,設計上需要玩家把AOE圈覆蓋到火獄之楔(柱子)上,幫忙處理柱子進度。
- **Garuda P1的刺羽小怪**(死亡大暴風):需要坦克/近戰盡快控制住並拉離人群,沒有拉走的話,死亡瞬間會在牠所在位置造成大暴風高傷害,若那個位置剛好是raid堆疊處就會波及一大群人。

**團隊自己怎麼稱呼這些技能(俗稱/黑話)是每個團隊自己的事,不寫在這份共用檔案裡**——查FFLogs死亡明細對照死者職業/場上角色,用上面這些機制事實去判斷,而不要預期任何團隊的俗稱都長一樣。
