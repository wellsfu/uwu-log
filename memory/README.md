# memory/ — 純技能事實資料庫

給 Claude Code(或任何協助寫死亡片段死因分析的人/AI)查閱用的**純技能事實**資料庫,不限定任何一個副本。分成兩個獨立子系統,分別對應「王放了什麼」「玩家手上有什麼」的技能事實(名稱/分類/目標範圍/傷害效果),**不含死因判讀或戰術建議**——死因判讀、「這隻王怎麼打」的攻略內容放在 repo 根目錄的 `<ENCOUNTER>_MECHANICS.md`(例如 `../UWU_MECHANICS.md`)裡,兩者是分開的兩份責任:`memory/` 回答「這個技能客觀上做了什麼」,`*_MECHANICS.md` 回答「這為什麼會死、該怎麼應對」。

```
memory/
├── class-abilities/<LV>/<Job>.md   — 職業技能事實(玩家手上有什麼)
└── encounters/<NAME>/              — 王技能事實(王放了什麼)
    ├── README.md                   — 該副本的索引(來源、同步等級、跨Boss同名技能警告、各Boss/Phase檔案清單)
    └── <Boss>.md                   — 每個Boss/Phase各自的技能事實表
```

## `class-abilities/<LV>/<Job>.md` — 職業技能參考

- **`<LV>`**:角色同步等級,對應「玩家在這場戰鬥裡實際能用的技能停在哪個等級」。每個副本同步的等級不一定相同,要查哪個等級的技能表,以該副本自己的 `encounters/<NAME>/README.md` 寫的同步等級為準。目前只有 `70/`,是目前這個 repo 已經支援分析的副本用到的等級;之後如果要支援同步在其他等級的副本,依樣新增 `class-abilities/80/`、`class-abilities/90/` 等資料夾,內部結構、檔案格式都比照 `70/` 即可,不要跟現有等級的資料夾混在一起。
- **`<Job>.md`**:職業識別碼,對應 `../web/app.js` 裡 `ROLE_MAP` 使用的**英文**職業名稱(例如 `Paladin`、`WhiteMage`、`BlackMage`),不是中文職業名、也不是縮寫(例如不是 `PLD`)。查表前先看 FFLogs/`data.js` 裡的職業欄位是哪個英文字串,直接對應同名的 `.md` 檔案。

每個職業檔案的格式:

- **用途 / 來源**:這份資料適用的同步等級與資料來源(現行版本 huijiwiki 職業頁面)。
- **GCD 技能**:會佔用「公共冷卻時間(GCD)」的技能,通常是連段輸出、主要治療咒語。
- **OGCD 技能**:不佔用 GCD、可以穿插在 GCD 之間使用的技能,通常是減傷/護盾/位移/爆發/嘲諷等工具技。
- **只列「該同步等級當下實際會用到的最新版本」技能,不標示解鎖等級**——如果同一個按鍵在升級過程中被替換過(例如白魔法師的壘石→崩石),表格裡只會出現崩石,不會兩個都列。真正各自獨立的連段技能(例如同一套連段的第一擊/第二擊/第三擊)則會分別列出,不會被誤merge成一個。
- **分類欄位**常見標籤(不同職業會依實際情況增減):單體傷害、群體傷害、單體治療、群體治療、減傷、護盾、嘲諷、解除嘲諷、位移、控場(暈眩/擊倒/沉默等)、增傷buff、資源技、爆發技、自我治療、淨化、復活、團隊增益、其他/被動連結。
- **詠唱時間 / 冷卻時間欄位**:每個技能各自的詠唱時間(瞬發 = 無詠唱)與冷卻時間(OGCD 都是瞬發,但各自有獨立CD;一般連段用GCD技能冷卻時間顯示標準的2.5秒)。數值來自 huijiwiki 各技能自己的 Action 詳情頁(咏唱时间/复唱时间欄位),已考慮該同步等級是否已解鎖會縮短CD的特性(例如某些技能的CD縮短特性要到70級以上才生效,此時表格顯示的是縮短前的原始數值)。共用CD、限定充能次數、無法手動放上快捷欄等特殊情況會在該欄位或用途/效果欄位額外註記。
- **`<LV>` 級當下的重點提醒**:給死因分析用的實戰重點,例如關鍵技能CD多長、有沒有發動限制、哪個是唯一的位移手段。

### 職業的「轉職樓層」跟同步等級是兩回事

有些職業(例如絕槍戰士/舞者從 60 級起算、賢者/鐮鐮客從 70 級起算、蝰蛇劍士/繪靈法師從 80 級起算)只能在角色達到特定等級後才能解鎖,解鎖當下角色等級已經高於這個「轉職樓層」。**這跟角色能不能被同步進某場戰鬥是兩件事**:只要玩家帳號上已經解鎖了這個職業,不管轉職樓層多高,理論上都能被同步進任何等級的內容——這些職業的技能在 wiki 上標示的「解鎖等級」是該職業自身進度表上的內部序號,不是玩家實際要達到的角色等級,一轉職當下這些序號全部同時到手。因此同步到某個等級時,實際持有的技能就是「所有內部序號 ≤ 該同步等級」的技能——如果轉職樓層本身就高於同步等級(例如蝰蛇劍士轉職樓層80、同步在70),能用的技能自然會比轉職樓層低於或等於同步等級的職業少很多,這是正常現象,不是資料缺漏。

### 職業的另一種例外:設限特職

`BlueMage.md`(青魔法師)沒有技能表,只有簡短說明——青魔法師是「設限特職(Limited Job)」,設計上就不能用任務搜索器排到絕大多數高難度內容(尤其是絕/究極系列),這是遊戲規則層級的參加資格限制,跟上面「轉職樓層 vs 同步等級」完全是兩回事,不會因為換一個同步等級不同的副本就改變。如果分析的副本允許青魔法師參加(目前已知的絕/究極系列都不允許),需要另外確認再決定是否要補上技能表。

## `encounters/<NAME>/` — 王技能事實參考

- **`<NAME>`**:副本識別碼,目前只有 `UWU`(絕・究極武器破壞作戰),對應這個 repo 目前唯一支援分析的副本。新增其他副本時,依樣新增 `encounters/<新副本代號>/` 資料夾即可,不需要改動這份 README 描述的結構。
- **`README.md`**:每個副本資料夾自己的索引,內容包含:資料來源(huijiwiki)、這個副本固定同步的等級(用來對應 `class-abilities/<LV>/`)、跨階段/跨Boss同名技能的警告(同一個技能名稱可能在不同Boss身上重複使用,或同一隻王身上不同招式剛好同名,查表時要注意分辨)、各階段大約時長總覽(純粹用來定位死亡時間點對應哪個Boss/Phase,不含死因判讀)、底下每個 `<Boss>.md` 檔案的索引與簡介。
- **`<Boss>.md`**:每個Boss/Phase各自的**純技能事實表**——技能名稱、分類、目標/範圍、傷害或效果數據,格式比照 `class-abilities/<LV>/<Job>.md`,**不含死因判讀或戰術建議**。如果某個技能是從其他Boss檔案「沿用」的(常見於多階段組合的最終戰,會重複使用前面幾隻王的招式),該Boss檔案只會簡述+標註參照哪一份檔案有完整說明,不會整段複製。查死因判讀本身要到 repo 根目錄對應的 `<ENCOUNTER>_MECHANICS.md`,不是這裡。

## 查表流程

死因分析的完整查表流程(何時查 `*_MECHANICS.md`、何時查 `memory/`)寫在 `.claude/skills/death-cause-analysis/SKILL.md` 裡,不在這裡重複。簡單說:`*_MECHANICS.md` 是死因判讀的主要查表對象,`memory/` 只在需要更精確的技能事實數據時輔助查證。
