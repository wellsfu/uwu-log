# memory/ — 職業技能死因分析參考資料

給 Claude Code(或任何協助寫死亡片段死因分析的人/AI)查閱職業技能用的參考資料庫。跟 `../UWU_MECHANICS.md`(王的機制表)是同一套用途,一個查王放了什麼、一個查玩家手上有什麼。

## 目錄結構:`memory/<LV>/<Job>.md`

- **`<LV>`**:角色同步等級。目前只有 `70`,對應這個 repo 主要分析的內容——UWU(絕・究極武器破壞作戰)固定同步在 70 級。
  如果未來這個 repo 要涵蓋同步等級不同的內容(例如其他絕本/零式副本),依樣新增 `memory/80/`、`memory/90/` 等資料夾,內部結構、檔案格式都比照 `memory/70/` 即可,不要跟現有等級的資料夾混在一起。
- **`<Job>.md`**:職業識別碼,對應 `../web/app.js` 裡 `ROLE_MAP` 使用的**英文**職業名稱(例如 `Paladin`、`WhiteMage`、`BlackMage`),不是中文職業名、也不是縮寫(例如不是 `PLD`)。查表前先看 FFLogs/`data.js` 裡的職業欄位是哪個英文字串,直接對應同名的 `.md` 檔案。

## 查表流程

1. 從 FFLogs 死亡明細找到死亡玩家的職業(英文識別碼)與死亡當下的時間點。
2. 到 `memory/<內容對應的同步等級>/<職業識別碼>.md`,查這個職業在該同步等級下實際持有哪些技能。
3. 對照死亡時間點前後,判斷玩家手上該有的減傷/護盾/位移/爆發治療手段是否還在CD、有沒有用出來——這是死因判讀「機制沒躲開」vs「減傷沒開」vs「補量不夠」的依據。
4. 王本身放的技能機制查 `../UWU_MECHANICS.md`,不在這個資料夾裡。

## 每個職業檔案的格式

- **用途 / 來源**:這份資料適用的內容與資料來源(現行版本 huijiwiki 職業頁面)。
- **GCD 技能**:會佔用「公共冷卻時間(GCD)」的技能,通常是連段輸出、主要治療咒語。
- **OGCD 技能**:不佔用 GCD、可以穿插在 GCD 之間使用的技能,通常是減傷/護盾/位移/爆發/嘲諷等工具技。
- **只列「該同步等級當下實際會用到的最新版本」技能,不標示解鎖等級**——如果同一個按鍵在升級過程中被替換過(例如白魔法師的壘石→崩石),表格裡只會出現崩石,不會兩個都列。真正各自獨立的連段技能(例如同一套連段的第一擊/第二擊/第三擊)則會分別列出,不會被誤merge成一個。
- **分類欄位**常見標籤(不同職業會依實際情況增減):單體傷害、群體傷害、單體治療、群體治療、減傷、護盾、嘲諷、解除嘲諷、位移、控場(暈眩/擊倒/沉默等)、增傷buff、資源技、爆發技、自我治療、淨化、復活、團隊增益、其他/被動連結。
- **`<LV>` 級當下的重點提醒**:給死因分析用的實戰重點,例如關鍵技能CD多長、有沒有發動限制、哪個是唯一的位移手段。

## 不會出現在死亡紀錄裡的職業

`Viper.md`、`Pictomancer.md`、`BlueMage.md` 沒有技能表,只有簡短說明——這三個職業因為轉職等級門檻(蝰蛇劍士/繪靈法師的職業任務要求角色 100 級起跳,高於 UWU 的 70 級同步)或設限特職規則(青魔法師無法排入絕/究極系列副本),不可能出現在 70 級同步的 UWU 死亡紀錄裡。如果未來新增其他同步等級的資料夾,這三個職業是否適用需要重新判斷(例如同步 100 級的內容蝰蛇劍士/繪靈法師就可能適用)。
